# v0.0.14

MySQL prepared statements and PostgreSQL describe/binary rows land. SQL failures map to dialect error codes. `UPDATE` / `DELETE` can affect many rows. Real `psycopg2` and `PyMySQL` clients are covered.

## Features

- Implement the MySQL prepared statement protocol ([@aster](https://github.com/aster))
- Describe PostgreSQL statements from the catalog and encode binary result rows ([@aster](https://github.com/aster))
- Scan and update or delete every row that matches a predicate ([@aster](https://github.com/aster))
- Bind `NOT`, `IS NULL`, and `IN (SELECT …)` as real predicates ([@aster](https://github.com/aster))
- Interoperate with real `psycopg2` and `PyMySQL` clients ([@aster](https://github.com/aster))

## Bug Fixes

- Accept `START TRANSACTION` and normalize builtin function names ([@aster](https://github.com/aster))
- Map bind, plan, and execution failures to protocol-specific SQLSTATE / error numbers ([@aster](https://github.com/aster))
- Keep integer literals exact and reject out-of-range numbers ([@aster](https://github.com/aster))
- Keep SQL `NULL` distinct from empty strings with three-valued logic ([@aster](https://github.com/aster))
- Surface transaction conflicts on both MySQL and PostgreSQL wires ([@aster](https://github.com/aster))
- Return an empty result for `LIMIT 0` ([@aster](https://github.com/aster))
- Compare large integers with floats without rounding away precision ([@aster](https://github.com/aster))
