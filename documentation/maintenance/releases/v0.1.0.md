# v0.1.0

First 0.1 release. Catalog ownership can fence multi-node leadership. `LIMIT` / `OFFSET` paging keeps the offset. Unsupported VOS composite column types such as `file` and `vector` fail at bind instead of silently degrading.

## Features

- Persist catalog owners and reject stale fence tokens on the executor ([@aster](https://github.com/aster))
- Keep `LIMIT` and `OFFSET` as real expressions so paging no longer drops offsets ([@aster](https://github.com/aster))
- Reject unsupported VOS composite types such as `file` and `vector` at SQL bind time ([@aster](https://github.com/aster))

## Bug Fixes

- Drop pre-1.0 catalog format compatibility shims; only the current format version is accepted ([@aster](https://github.com/aster))
- Keep pytest harness modules out of plain `unittest` discovery ([@aster](https://github.com/aster))

## Breaking Changes

- Catalog files must match the current format version exactly; older formats are rejected ([@aster](https://github.com/aster))
- SQL statements that touch `file` / `vector` (and similar Unknown composites) fail at bind instead of silently degrading ([@aster](https://github.com/aster))
